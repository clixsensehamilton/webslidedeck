## Hook
This week established that data science runs on three pillars. Here's the operational read: IT doesn't just touch this stack — IT owns the pillar that everything else depends on, and has partial stake in the other two.

## Scene 1 — The CS Pillar Is IT's Home Ground
The computer science pillar covers data engineering, pipeline construction, storage architecture, access control, and the infrastructure that moves data from origin to model. These aren't adjacent IT responsibilities — they are core IT functions. Without reliable pipelines, clean data flows, and governed access, no algorithm trains correctly, no model deploys cleanly, and no inference returns in time. The math pillar is impressive. The CS pillar is foundational.

## Scene 2 — The Pipelines IT Builds Shape What the Model Knows
This is where the operational weight lands. A model can only learn from data it can reach, in the format it can read, with the quality that the pipeline maintains. When data is incomplete, duplicated, or siloed behind access controls that were never updated for ML use cases, the model's ceiling is set before training even begins. IT's pipeline decisions are model design decisions, whether IT knows it or not.

## Scene 3 — What This Week Sets Up
Next week we'll go one level deeper into the AI/ML/DL stack itself — what these layers actually are, how they relate to each other, and where the tools your organisation uses today fit within them. The three-pillar framework is the map. Next week we start naming what's on it.

## Takeaway
IT isn't a supporting actor in the AI story — it's the infrastructure owner, and infrastructure is where AI either runs or doesn't.
